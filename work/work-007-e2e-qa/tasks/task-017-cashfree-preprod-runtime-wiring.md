## Objective

The frontend must never receive provider secrets.

## Scope

- In scope: environment-specific non-secret provider settings in deployment YAML; validated rendering into `deploy.env`; API-only access to Cashfree credentials from the selected environment's runtime backend secret files; preprod selects Cashfree sandbox; production selection is explicit and never falls back to preprod; local Compose remains Mock; tests and security checks. Also ensure the verification response identifies its server-bound order number, and verify any guest payment authorization/return path cannot expose or mutate another customer's order. Document the concrete trust boundary and add negative tests before returning.
- Out of scope: frontend checkout work, reading/changing credential values, live payment, production deployment, changing SOPS recipients.

## Security validation

- Changed trust boundary: encrypted SOPS backend values (`CASHFREE_APP_ID`, `CASHFREE_SECRET_KEY`) become API runtime secret files (`/run/secrets/cashfree_app_id`, `/run/secrets/cashfree_secret_key`) via `bootstrap_secrets.sh` (`0600` permissions); payment verification return boundary returns server-derived `orderNumber` and enforces `providerOrderId` binding on guest payment verification/lookup before any idempotent return or gateway status mutation.
- Controls: strict per-environment config (`resolve_environment` in `scripts/deploy_vps.py` blocks `mock`/`sandbox`/`secrets/encrypted` in `prod` and requires `sandbox` in `preprod`), API-only file mounts (`backend/docker-compose.yml` and `docker/compose.preprod.yaml`), `0600` permissions, no plaintext in artifacts/deploy config, local Mock retained (`docker/compose.yaml`), no preprod-to-prod fallback, no secret in responses/bundles/logs.
