# Work 010 decisions

- **DEC-010-001 — Database is the source of truth.** Occasion content, visibility, schedule, ordering, image, and product associations come from backend/database responses; frontend contains only reusable presentation.
- **DEC-010-002 — Seasonal occasions are admin-controlled.** Only enabled seasonal occasions inside their optional `Asia/Kolkata` schedule appear. Hidden or out-of-season records remain manageable in admin but are omitted from the storefront. The prior rule that evergreen records ignore admin visibility/scheduling is superseded by DEC-010-010.
- **DEC-010-003 — Products can have multiple occasion associations.** Reuse product records and SKUs; do not duplicate products for each gift occasion.
- **DEC-010-004 — One distinct relevant image per visible occasion.** Reject duplicate assignments and inspect the actual imagery; different URLs alone do not satisfy uniqueness.
- **DEC-010-005 — No empty section.** Omit the homepage grid only when there are no eligible occasions. The prior assumption that four evergreen cards always keep it populated is superseded by DEC-010-010; admin may disable any occasion.
- **DEC-010-006 — Release gate.** Local Docker/API/database and browser verification plus owner review are required before push or VPS deployment.
- **DEC-010-007 — Earlier evergreen rule (superseded 2026-10-03).** The former rule kept Birthday, Anniversary, Wedding, and Baby Shower visible year-round and grouped seasonal cards first. Current defaults and visibility behavior are defined by DEC-010-010; API order is rendered as received.
- **DEC-010-008 — Occasion art must tell the occasion story.** Birthday should feel like a joyful modern celebration with a Sulocraft handmade gift; Anniversary should show a husband meaningfully gifting his wife a handmade Sulocraft product; Wedding should feel like a bright contemporary wedding gift moment. A generic heart-only graphic or dark/dull scene is insufficient.
- **DEC-010-009 — Occasion business rules stay server-owned.** Admin UI consumes API-returned visibility/schedule metadata and ordering; it does not maintain its own list of occasion names or sort homepage cards. Any immutable-evergreen behavior is superseded by DEC-010-010.
- **DEC-010-010 — Five initial defaults are enabled; all occasions stay admin-controllable.** As of 2026-10-03, only Birthday, Just Because, Anniversary, Baby Shower, and Wedding should be enabled in the default database state. The former immutable evergreen rule is superseded; admin may enable/disable any occasion. Other rows remain available but disabled unless an admin enables them.
- **DEC-010-011 — Occasion assets must be checked against delivery.** A populated database image field is insufficient: every displayed URL must return a usable image, and each occasion must have distinct relevant artwork. The backend/database owns these URLs; the frontend only renders them.
