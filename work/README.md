# Agent workspaces

GitHub Projects and Issues provide the human-facing view of major work: backlog, priority, owner, dependencies, milestone, area, environment, and high-level status. Each significant work item maps to one GitHub Issue after existing GitHub state is inspected.

`work/` remains the agent execution and coordination layer. It preserves detailed subtasks, contracts, handoffs, decisions, blockers, validation evidence, and history. Do not create GitHub Issues for every small implementation step or duplicate the full backlog in another file.

Start at [`INDEX.md`](INDEX.md), then read only the selected work item's README, task list, decisions, coordination file, and assigned task contract. GitHub wins when a verified high-level status conflicts; reconcile the work summary without overwriting technical execution history.

Existing Work IDs and directories remain intact until their Issue mappings and all repository references are inventoried. When a safe issue-numbered path migration is done, update every reference and preserve the original task records and history.
